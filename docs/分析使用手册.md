# 分析使用手册（趋势 / 长线版）

这份手册不是讲“怎么启动程序”，而是讲：

> 你应该怎么理解这个系统里的结果，尤其是针对 **趋势、长线、MA20 / MA60 / MACD** 的使用方式。

---

## 1. 这套系统最适合拿来干什么

它最适合：

- 指数 / ETF 趋势研究
- 波段 / 长线观察
- 低频辅助决策
- 通过多个层次把“原始行情”加工成“更容易理解的信号”

它不是高频交易系统，也不是日内执行系统。

---

## 2. 这套系统的分析顺序

你可以把它理解成 7 层：

1. **行情层**：`daily_bar`
2. **指标层**：MA / EMA / MACD / RSI / ATR / VOL_MA
3. **宏观层**：`macro_snapshot`
4. **环境层**：scope-aware `market_regime + environment_snapshot`
5. **轮动层**：谁更强、谁在领涨
6. **策略层**：四类策略偏好评分
7. **信号层**：最终 BUY / WATCH / HOLD / REDUCE / SELL

也就是说：

> 它不是只给你一条买卖信号，而是把“为什么会有这条信号”也一层层展开给你看。

---

## 3. 你最该关注的三个核心指标

你前面已经明确偏向：

- 趋势
- 长线
- MA20
- MA60
- MACD

所以你的核心阅读顺序应该是：

### 3.1 先看 MA20 / MA60

最简单的趋势判断方法：

- **价格在 MA20 上方**：短中期偏强
- **MA20 在 MA60 上方**：趋势结构偏强
- **价格在 MA60 上方**：中期趋势没有被破坏

更理想的状态是：

> **价格 > MA20 > MA60**

这通常说明趋势是比较顺的。

### 3.2 再看 MACD

MACD 主要看三件事：

- `macd` 是否在 0 轴上方
- `macd_hist` 是否转强
- 是否出现明显背离或走弱

对趋势系统来说：

- MA 负责看“结构”
- MACD 负责看“动能”

### 3.3 最后看量能

系统里有：

- `vol_ma20`
- `vol_ma60`

量能不是你第一优先级，但它可以帮助你判断：

- 走势是否有资金支持
- 突破是不是“虚的”

---

## 4. Market Regime + Environment Layer 应该怎么用

`Market regime` 不是用来替代个别标的判断的，
而是用来判断：

> **当前整体环境，是顺风、震荡，还是逆风。**

你可以这样理解：

- `risk_on`：更适合积极看强势方向
- `neutral`：更适合选择性观察
- `risk_off`：更适合谨慎、控制仓位、避免追高

现在还要配合 `Environment layer` 一起看，它会把：

- breadth
- liquidity proxy
- stress proxy

拆出来给你看。

你可以粗略理解成：

- `regime`：环境结论层
- `environment`：环境拆解层

### 现在的 scope 语义

桌面端和 CLI 的 `GLOBAL / CN / HK` 已经是**真正按 scope 读取 regime / environment**：

- `GLOBAL`：全局聚合视角
- `CN`：中国市场视角
- `HK`：香港市场视角

所以当你切换 scope 时，对应的环境层解释会一起变化。

但要额外注意一个 Phase 1 边界：

> **当前 dashboard/report 的 regime / environment 已经是 scope-aware；signal / backtest 结果则需要继续结合它们自己的 provenance 字段（如 analysis scope / regime basis / snapshot match）一起理解。**

所以：

- `CN / HK` scope 下的环境解释已经本地化
- `signal` / `backtest` 不应只根据当前 dashboard scope 直觉理解，必须结合 provenance 一起读

### 你的用法建议

如果你看见：

- 个别标的很强
- 但 `regime` 明显偏差

那说明：

> 这可能是局部强，不一定是环境级机会。

所以对你这种偏长线的人来说，`regime` 的作用更像：

- **控制节奏**
- **决定是不是该积极出手**

---

## 5. Rotation（轮动）应该怎么用

`Top rotation` 不是直接告诉你“必须买谁”，而是告诉你：

> 当前市场里，哪些方向更强，哪些方向更弱。

你可以把它当作“风格和主线强度榜”。

### 对你更合适的用法

不要把 rotation 当成追涨榜。

而是：

- 如果某个方向本来就在你的观察名单里
- 它同时又出现在高位 rotation
- 并且 MA20 / MA60 / MACD 结构也好

那么这个方向就更值得重点看。

---

## 6. 四类策略偏好应该怎么理解

系统里有四类策略：

- `VALUE_LEFT`
- `TREND_PULLBACK`
- `TREND_BREAKOUT`
- `MOMENTUM_RIGHT`

### 如果你偏趋势 / 长线

最重要的是这两类：

#### `TREND_PULLBACK`

意思是：

- 大趋势还没坏
- 但价格出现了阶段性回踩
- 这是“顺趋势等回撤”的思路

这通常比纯追涨更符合长线交易者。

#### `TREND_BREAKOUT`

意思是：

- 趋势结构已经形成
- 当前处于强势突破阶段
- 更偏“确认后跟随”

### 怎么看分数

你不用执着绝对数值，主要看：

- 哪一类分数最高
- 是否明显高于其他策略
- `alignment` 是否高

如果 `alignment` 高，说明：

> 不是只有一种模型觉得它好，而是多个角度都在支持它。

---

## 7. 最终信号怎么用

最终信号不是孤立的，它是：

- 策略偏好
- 宏观环境
- 轮动强弱
- 一致性

综合后的结果。

标签大致可以这样理解：

- `STRONG_BUY`：很强的综合支持
- `BUY`：偏积极
- `WATCH`：有看点，但还不够强
- `HOLD`：维持观察或持有
- `REDUCE`：谨慎、偏减仓
- `SELL`：明显转弱或不合适继续持有

### 对你更合理的用法

你不需要见到 `BUY` 就马上动作。

你更适合这样看：

1. 先看趋势结构（MA20 / MA60）
2. 再看 MACD 是否支持
3. 再看 `regime` 是否顺风
4. 最后把 `signal` 当成综合确认层

也就是说：

> `signal` 对你来说更像“综合结论”，不是唯一决策来源。

再补一句：

> `signal` 是带 provenance 的综合结果；`regime + environment` 是当前 scope 的环境解释层；两者需要一起看，而不是互相替代。

---

## 8. Data Health 为什么重要

这个系统已经加入了数据健康检查，所以在你看趋势之前，应该先确认：

- 数据有没有缺口
- 有没有异常跳变
- provider 有没有异常
- 有些标的是不是 fallback 才拿到的数据

### 为什么这对你尤其重要

因为你看的是：

- MA20
- MA60
- MACD

这些都特别怕：

- 序列断裂
- 复权口径漂移
- 异常大跳点

所以你的分析顺序应该是：

> **先看 Data Health，再看趋势。**

现在建议把它进一步收敛成：

> **先看 Trust summary，再下钻 Pipeline freshness 和 Data Health。**

原因是：

- `Trust summary` 先给出这次结果是否可信的总判断
- `Pipeline freshness` 再告诉你分析链有没有跑到最新日期，以及最新日是否完整
- `Data Health` 最后告诉你这些数据里有没有 gap / jump / provider 风险

---

## 9. 桌面端应该怎么读

### 顶部先看 scope + 三个日期

- `Scope`
- `Selected analysis date`
- `Latest available analysis`
- `Regime as-of date`

再看：

- `Trust summary`
- `Pipeline freshness`
- `Data health`

如果 `Selected analysis date` 和 `Regime as-of date` 不一样，说明：

> 宏观环境还没更新到你当前看的那一天，系统是在用最近一次可用宏观数据。

这并不自动表示错误。

更准确的理解是：

- 价格 / 指标 / 信号可能已经更新到最新交易日
- 宏观因子由于发布时间滞后，只能用最近一次可用值 forward-fill

### 然后看下面几块

1. `Market regime`
2. `Environment layer`
3. `Top rotation`
4. `Top signals`
5. `Data health`

同时要补一个当前版本最重要的理解：

- `Trust summary` 负责先回答“这次结果能不能信”
- `Top signals` 要继续看 signal provenance（analysis scope / regime basis）
- `Latest backtest` 要继续看它是否 matches current snapshot

其中：

- `Market regime` 适合看结论：当前是 `risk_on / neutral / risk_off`
- `Environment layer` 适合看原因：breadth 是修复还是走弱、流动性 proxy 是否支撑、压力项是否偏高

### 历史复盘怎么做

- 用日期选择器切到历史日期
- 看当时的 signal / rotation / regime 组合
- 对照后面的走势

这对你训练自己的趋势判断很有帮助。

---

## 10. 适合你的实际决策方式

如果你偏长线、趋势，建议你这样使用：

### 优先考虑

- MA20 / MA60 结构没坏
- MACD 不是明显死叉走弱
- `TREND_PULLBACK` 或 `TREND_BREAKOUT` 靠前
- `regime` 不是明显恶劣
- `Data health` 没严重问题

### 谨慎处理

- 纯短期冲高但 MA 结构不稳定
- `rotation` 很强但 `regime` 很差
- `signal` 好看但数据健康有明显告警
- `pipeline freshness` 显示最新日不完整

---

## 11. 一句话总结你的使用方式

如果你只记一句话，就记这个：

> **先确认数据没问题，再看 MA20 / MA60 与 MACD 的趋势结构，最后用 regime、environment、rotation 和 signal 做综合确认。**

再补一句更完整的版本：

> **先看 trust summary 判断这次结果能不能信，再用 pipeline freshness 和 data health 做证据下钻，最后再读趋势结构和综合信号。**

这就是这套系统当前最适合你的用法。

## 12. 使用 LLM 研究层辅助解读（V4.5）

V4.5 Research Layer 是**冻结量化引擎之上的只读叙事层**，不是替代你的判断，而是提供 AI 视角的交叉验证和叙事解读。

**核心原则**：
- 只读：解释、质疑、提供上下文、讲述历史
- 禁止：创建信号、评分、排序、覆盖决策、参与执行
- 输出：Markdown 纯文本，无 JSON schema、无 confidence、无 score、无 ranking

### 12.1 什么时候用 LLM 分析

推荐在以下场景触发：

- **新信号出现时**：regime 刚发生状态转换，需要快速理解背后的宏观驱动因素
- **rotation 剧烈变化时**：领涨/领跌板块突然换位，需要 AI 辅助梳理逻辑
- **signal 与你的主观判断冲突时**：用 AI 的"第三视角"检查自己是否遗漏了某些维度
- **准备写投资笔记时**：让 AI 生成一份叙事草稿，作为你思考的起点

### 12.2 五个研究动作

Research Layer 提供 5 个固定按钮，每个按钮对应一个不同的系统 prompt 角色：

| 动作 | 中文名 | 角色 | 任务 |
|------|--------|------|------|
| `market_story` | 市场叙事 | 资深研究员 | 今天市场发生了什么 |
| `explain_decision` | 解释决策 | 系统分析师 | 为什么系统做出这样的决策 |
| `preclose_review` | 收盘前复核 | 执行分析师 | 为什么 Execution 给出这样的建议 |
| `risk_view` | 风险视角 | 风控总监 | 我最担心什么 |
| `devils_advocate` | 唱反调 | 质疑者 | 系统可能错在哪里 |

**建议**：
- 日常先看 `market_story` 理解市场背景
- 当信号与状态矛盾时，用 `explain_decision` 排查原因
- 盘中或收盘前，用 `preclose_review` 理解 Execution 建议
- 任何时刻都可以用 `risk_view` 和 `devils_advocate` 做压力测试

### 12.3 如何阅读 AI 分析报告

LLM 返回的报告是 Markdown 纯文本，没有结构化字段。通常包含：

1. **市场状态概述** — 当前 regime + environment 的叙事描述
2. **关键驱动因素** — 哪些宏观因子或技术面特征主导了当前状态
3. **信号解读** — 对 top rotation / top signal 的逐条解释
4. **风险提示** — AI 识别的潜在风险点

**关键原则**：

- AI 分析是**参考**，不是**指令**
- 输出中**没有** confidence、score、ranking、probability — 如果看到数字，那是系统喂给 LLM 的原始数据，不是 LLM 的评分
- 特别留意 AI 提到的"与历史模式相似性"，这往往是你自己容易忽略的长周期视角
- 如果 AI 提到的风险点和你自己的 checklist 不重叠，优先采纳你的 checklist；如果重叠，提高警觉

### 12.4 与 CLI 的关系

| 场景 | 推荐方式 |
|------|----------|
| 日常快速分析 | **桌面端「智能分析」按钮**（5 个按钮任选） |
| 批量/脚本化分析 | CLI `analyze-with-llm --action <action>` |
| 配置变更 | CLI `set-llm-config` / `set-llm-api-key` |

**注意**：V4.5 已删除 Agent Profile、Skill Registry、技能路由、比较分析、历史记录。只保留 5 个按钮的纯 Markdown 输出。
