# 日常操作手册（极简版）

这份手册适合你每天快速使用系统，不讲底层原理，只讲怎么跑。

---

## 1. 第一次使用（只做一次）

### 1.1 启动数据库

```bash
docker compose -f infra/docker/docker-compose.yml up -d
```

### 1.2 初始化数据库结构

```bash
cargo run -p quant-cli -- init-storage
```

### 1.3 导入标的池

```bash
cargo run -p quant-cli -- seed-universe
```

## 2. 每天怎么更新分析

建议在 **收盘后** 跑一次完整流程。

如果你只是白天临时看一眼，也可以手动跑，但趋势系统仍然以日线完成数据为主。

默认用户路径建议是：

> **优先使用桌面端的 `Refresh data` 作为默认刷新入口；CLI 命令继续保留为显式工程/高级用户路径。**

### 2.1 V3 推荐路径：一键同步导出

V3 新增的 `sync-and-export` 是当前**最推荐的 CLI 每日更新方式**：

```bash
cargo run -p quant-cli -- sync-and-export --scope global
cargo run -p quant-cli -- sync-and-export --scope cn
cargo run -p quant-cli -- sync-and-export --scope cn --date 2026-05-07
```

**说明**：

- 自动检查 latest gate 状态
- 若数据落后，自动执行全链路刷新（ingest → indicators → macro → rotation → strategy → signals → backtests）
- 刷新完成后自动导出日报
- 带 `--date` 时直接导出指定日期（跳过刷新）
- 若刷新后 gate 仍未通过，会 fail-loud 并提示运行 `explain-latest-gate` 排查

**一条命令完成全链路，是当前最推荐的 CLI 路径。**

### 2.2 V3 CLI 进度输出

V3 长耗时命令默认向 stderr 输出进度：

```bash
# 默认显示进度
cargo run -p quant-cli -- refresh-all --to 2026-05-08
# 输出：
# [1/7] Starting ingest...
# [2/7] Computing indicators...
# ...
# [7/7] Running backtests...

# 抑制进度输出（仅保留 stdout JSON）
cargo run -p quant-cli -- --quiet refresh-all --to 2026-05-08
```

说明：
- `--quiet` 是全局选项，放在子命令之前
- 进度输出到 stderr，stdout JSON 报告不受影响
- 适用于脚本场景或需要干净 JSON 输出时

### 2.3 传统路径：更新日线数据

```bash
cargo run -p quant-cli -- ingest-daily --from 2025-01-29 --to 2026-03-13
```

> 实际使用时，把 `from` 改成你上次更新之后的日期，把 `to` 改成今天。

### 2.4 重跑全链路分析

> **这组命令必须按顺序执行**。`compute-macro` 依赖 `compute-indicators` 的数据，`compute-signals` 依赖前面所有阶段。如果倒序执行，`export-report` 会因 latest gate 落后而被拒绝。

```bash
cargo run -p quant-cli -- compute-indicators
cargo run -p quant-cli -- compute-macro --from 2025-01-01 --to 2026-05-08
cargo run -p quant-cli -- compute-rotation
cargo run -p quant-cli -- compute-strategy-preferences
cargo run -p quant-cli -- compute-signals
```

补充说明：

- `compute-macro` 现在会重建 `macro_snapshot / market_regime / environment_snapshot / strategy_state`
- 如果某些 FRED 因子临时异常，但库里已有旧的宏观历史，系统会继续按 as-of 语义产出 scoped regime / environment
- 如果 provider 返回异常响应，失败项会显示在 `failed_items` 里
- 如果 `export-report` 报错说 latest dashboard date 落后，先运行 `explain-latest-gate` 查看哪个 stage 卡住了

### 2.5 做一次数据健康检查

```bash
cargo run -p quant-cli -- pipeline-dates
cargo run -p quant-cli -- explain-latest-gate
cargo run -p quant-cli -- check-data-health
# 或者使用 V7 工作流，同时检查并导出报告：
# cargo run -p quant-cli -- data-health
```

建议先看：

- `pipeline-dates`
  - 看各 stage 是否已经到最新日期
  - 看最新那一天是不是**全量完整**
  - 如果 `strategy_preference` 已到最新、但 `signal_snapshot` 仍落后，优先单独重跑一次 `compute-signals`
- `explain-latest-gate`
  - 快速查看为什么默认最新日期没有推进到 freshest market date
  - 直接显示哪些 stage lagging / incomplete
- `check-data-health`
  - 看 provider 是否异常
  - 看是否有 gap / jump / turnover 问题
  - 看宏观源是否只是发布时间滞后

### 2.4 导出日报

```bash
cargo run -p quant-cli -- export-report
```

> **默认 `export-report` 现在会在 latest gate 落后时直接失败，不再静默导出旧日期日报。** 如果报错，先运行 `explain-latest-gate` 查看哪个 stage 卡住，修复后再导出。
>
> 如果确实要导出历史日报，请显式传 `--date YYYY-MM-DD`：
> ```bash
> cargo run -p quant-cli -- export-report --date 2026-05-07
> ```

如果你还想导出数据健康报告：

```bash
cargo run -p quant-cli -- export-data-health-report
# 或者使用 V7 工作流，同时检查并导出：
# cargo run -p quant-cli -- data-health
```

### 2.5 桌面端默认刷新路径

如果你日常主要通过桌面端使用系统，更推荐：

1. 打开桌面端
2. 点击 `Refresh data`
3. 先看 `Trust summary`
4. 再看 `Pipeline freshness`
5. 再看 `Data health`
6. 最后再读 `Environment / Rotation / Signals / Backtest`

如果 refresh 失败：

- 可以直接使用 `Retry failed stage`
- 也可以把 refresh 起点切到 `ingest / indicators / macro / rotation / strategy / signals / backtests` 再继续跑
- 这适合已经确认上游数据没问题，只想从某个后续阶段重新推进的情况

## 3. V3 LLM 智能报告分析

V3 新增了将日报发送给大模型分析的能力，获取 AI 视角的操作策略建议。

### 3.1 配置 LLM（只需执行一次）

```bash
# 配置 LLM 参数
cargo run -p quant-cli -- set-llm-config \
  --base-url https://api.openai.com/v1 \
  --model gpt-4o \
  --timeout-secs 60

# 设置 API Key（存储在系统 keyring，安全优先）
cargo run -p quant-cli -- set-llm-api-key --key sk-xxxxxxxxxxxxxxxx
```

说明：
- 仅支持 OpenAI-compatible API（自定义 `base_url + model + api_key`）
- API Key 优先存储在 OS keyring（Windows Credential Manager），失败时回退到 SQLite（会打印警告）
- 配置和 Key 只需设置一次，后续自动读取

## 4. FRED 宏观数据配置（当前版本）

当前版本将 FRED 宏观数据获取改为**可配置开关**。当网络环境无法访问 FRED 时，可以禁用获取，系统会使用 ClickHouse 中已有的宏观数据。

### 4.1 查看 FRED 配置状态

```bash
cargo run -p quant-cli -- show-fred-config
```

### 4.2 启用 FRED 获取（默认行为）

```bash
cargo run -p quant-cli -- set-fred-config --enabled --api-key YOUR_FRED_API_KEY
```

说明：
- API Key 在 `config/fred.toml` 中管理（gitignored，参考 `config/fred.toml.example`）
- 支持环境变量引用：`api_key = "${FRED_API_KEY}"`
- `enabled = true` 时，`compute-macro` 和 `check-data-health` 会自动从 FRED API 获取数据

### 4.3 禁用 FRED 获取

当网络环境无法访问 FRED 时：

```bash
cargo run -p quant-cli -- set-fred-config --disabled
```

说明：
- 禁用后系统使用 ClickHouse 中已有的宏观数据（可能陈旧）
- `compute-macro` 会跳过 FRED 获取，但继续使用已存数据计算 regime
- `check-data-health` 会显示宏观因子状态为 `disabled`
- 再启用时直接运行 `set-fred-config --enabled --api-key ...`

### 3.2 分析报告

```bash
# 分析当前最新日报
cargo run -p quant-cli -- analyze-with-llm --scope global

# 分析指定日期
cargo run -p quant-cli -- analyze-with-llm --scope cn --date 2026-05-07
```

说明：
- 分析结果保存为 `reports/llm-analysis-{scope}-{date}.md`
- 可通过桌面端 `Recent reports` 查看和打开
- API Key 绝不会出现在 stdout、stderr、日志或错误信息中

### 3.3 安全约束

- API Key 存储优先使用 OS keyring
- Keyring 不可用时回退到 SQLite（明文，有警告提示）
- 任何输出中都不会包含 API Key
- 前端/桌面端不接触 API Key

## 4. V4.5 桌面端 Research Layer（推荐）

V4.5 Research Layer 是**冻结量化引擎之上的只读叙事层**，提供 5 个固定按钮，每个按钮对应一个不同的系统 prompt 角色，输出 Markdown 纯文本。

**核心原则**：
- 只读：解释、质疑、提供上下文、讲述历史
- 禁止：创建信号、评分、排序、覆盖决策、参与执行
- 输出：Markdown 纯文本，无 JSON schema、无 confidence、无 score、无 ranking

### 4.1 打开研究面板

在 Dashboard 顶部操作区找到 **「智能分析」** 按钮：

1. 点击 **「智能分析」**
2. 从 5 个按钮中选择研究动作：
   - **市场叙事** — 今天市场发生了什么
   - **解释决策** — 为什么系统做出这样的决策
   - **收盘前复核** — Execution 建议解读
   - **风险视角** — 风控总监视角
   - **唱反调** — 质疑系统结论
3. 系统会将当前 scope + date 的 dashboard snapshot 发送给 LLM，返回 AI 视角的 Markdown 分析报告。

### 4.2 面板功能

分析完成后，面板显示：

- **Markdown 分析报告** — LLM 返回的纯文本分析（三层 XSS 防御渲染）
- **导出按钮** — 一键导出当前分析为 `reports/llm-analysis-{scope}-{date}.md`，并自动注册到 Recent reports

### 4.3 配置 LLM（首次使用）

如果系统检测到 LLM 未配置：

1. 点击面板内的 **「配置 LLM」** 按钮
2. 填写：
   - **Base URL**：如 `https://api.openai.com/v1`
   - **Model**：如 `gpt-4o`
   - **API Key**：点击「设置 API Key」安全存储（优先 OS keyring）
3. 点击 **「保存配置」**

配置成功后，黄色提示条消失，可直接使用分析功能。

### 4.4 安全与降级

- **API Key 安全**：优先存储在 OS keyring，失败时回退到 SQLite（会打印警告）
- **Placeholder 降级**：未配置 API Key 时，系统自动使用 PlaceholderProvider 返回示例分析，UI 显示黄色提示条
- **XSS 防御**：分析结果经过三层过滤（HTML escape → markdown 转换 → DOMPurify 标签过滤）

### 4.5 与 CLI 的关系

| 场景 | 推荐方式 |
|------|----------|
| 日常快速分析 | **桌面端「智能分析」按钮**（5 个动作任选） |
| 批量/脚本化分析 | CLI `analyze-with-llm --action <action>` |
| 配置变更 | CLI `set-llm-config` / `set-llm-api-key` |

**注意**：V4.5 已删除 Agent Profile、Skill Registry、技能路由、比较分析、历史记录。只保留 5 个按钮的纯 Markdown 输出。

## 6. 桌面端怎么看

打开后你主要看这几块：

- **Scope selector**：切换 `GLOBAL / CN / HK`
- **Selected analysis date**：当前正在看的分析日期
- **Latest available analysis**：系统里最新可分析的日期
- **Regime as-of date**：宏观环境实际对应的日期
- **Trust summary**：这次结果能不能先拿来用的主判断
- **Environment layer**：breadth / liquidity proxy / stress proxy 的拆解结果
- **Pipeline freshness**：各 stage 的最新日期与最新日覆盖情况
- **Top rotation**：当前最强的轮动方向
- **Top signals**：当前最强的信号标的
- **Latest backtest**：最近一次回测结果
- **Data health**：数据质量与异常检查结果
- **Research Layer**：5 个按钮的只读叙事分析（Market Story / Explain Decision / Preclose Review / Risk View / Devil's Advocate），Markdown 纯文本输出（V4.5）

补充理解：

- `Trust summary` 解决的是：
  - **这次结果现在值不值得继续看**
  - **当前 scope、signal/backtest provenance 有没有明显冲突**
- `Pipeline freshness` 解决的是：
  - **这条链有没有跑到最新日期**
  - **最新那一天是不是全量完整**
- `Data health` 解决的是：
  - **数据本身有没有异常 / 缺口 / provider 风险**
- `Regime as-of date` 落后于 `Selected analysis date` 通常是正常的，表示宏观因子发布时间滞后，系统使用最近可用宏观值 forward-fill

## 9. 最短命令清单

### 每日更新

**推荐默认路径（V3 一键同步导出）：**

```bash
cargo run -p quant-cli -- sync-and-export --scope global
```

> `sync-and-export` 会自动检查 gate → 刷新（如需要）→ 导出日报，一条命令完成。

**替代路径（手动全链路）：**

```bash
cargo run -p quant-cli -- refresh-all --to 2026-05-08
```

> `refresh-all` 会按正确顺序依次执行：ingest → indicators → macro → rotation → strategy → signals → backtests，并在最后做一致性校验。

**收盘前执行过滤（V5 新增）：**

```bash
cargo run -p quant-cli -- preclose-analysis --scope cn
```

> `preclose-analysis` 会：
> - 读取当前 State（若 `NO_TRADE` 则全部跳过）
> - 筛选 `signal ≥ Buy` 的候选
> - 调用 Tencent API 获取实时快照
> - 运行 3 个 Pattern 判断执行时机（BuyNow / Wait / NoChase / Reduce / Skip）
> - 输出到 stdout，同时写入 `reports/execution-samples/YYYY-MM-DD.json`
> - 90 天内仅作为观测工具，禁止声称性能优势

**如需分步执行（工程/排障路径）：**

> **以下命令必须按顺序执行，不能倒序。**

```bash
cargo run -p quant-cli -- ingest-daily --from 2026-04-01 --to 2026-05-08
cargo run -p quant-cli -- compute-indicators
cargo run -p quant-cli -- compute-macro --from 2026-04-01 --to 2026-05-08
cargo run -p quant-cli -- compute-rotation
cargo run -p quant-cli -- compute-strategy-preferences
cargo run -p quant-cli -- compute-signals
cargo run -p quant-cli -- pipeline-dates
cargo run -p quant-cli -- check-data-health
cargo run -p quant-cli -- export-report
```

说明：

- `refresh-all` 会在末尾直接返回：
  - 本次 refresh window 为什么这样选
  - latest-date 是否推进
  - 哪个 stage lagging / incomplete
  - consistency / latest-gate 告警
- 当前 `refresh-all` 不再只按 `latest_daily_date - 7d` 做固定回看；
  - 如果 gated latest 落后于 source latest，
  - 或某个 scope 还没有 gated latest，
  - 系统会自动扩大一个保守 repair window，优先修复“被 gate 卡住但不是最新 7 天”的日期
- `--scope` 只决定 latest-date diagnostics / gate explanation 按哪个 scope 汇总，不表示只刷新该 scope 的底层数据。
- `--run-backtests` 当前默认为开启，与 desktop 完整 refresh 的语义保持一致。
- 分步命令仍然有效，但更适合作为**显式工程路径 / 高级用户路径**，以及需要手工排障时逐段执行。
- **默认 `export-report` 现在会在 latest gate 落后时直接失败，不再静默导出旧日期日报；如果确实要导出历史日报，请显式传 `--date YYYY-MM-DD`**。

**快速排查工具：**

如果你只想回答：

> “为什么默认最新日期还没上去？”

可以直接运行：

```bash
cargo run -p quant-cli -- explain-latest-gate
cargo run -p quant-cli -- explain-latest-gate --scope cn
```

它会直接返回：

- freshest market date
- latest available dashboard date
- 当前 scope 下哪些 stage lagging / incomplete
- 现有 signal/latest-gate alerts

### 打开桌面端

```bash
cargo run -p quant-desktop
```

### 回看历史

```bash

cargo run -p quant-cli -- dashboard-snapshot --date 2026-03-06
cargo run -p quant-cli -- dashboard-snapshot --scope cn --date 2026-03-06
```

## 11. V6 Research Surface 快速参考（可选）

如果你希望每天额外记录一些市场状态统计证据，可以在收盘后跑以下命令。它们是**只读观测工具**，不影响任何信号或执行逻辑。

```bash
# Signal-Regime Divergence：信号与状态是否背离
cargo run -p quant-cli -- research-srd --scope global

# Market Stretch：市场拉伸 / 拥挤 / 动量状态
cargo run -p quant-cli -- research-stretch --scope cn

# 条件前向收益统计：历史某条件后 N 日收益分布
cargo run -p quant-cli -- research analytics --condition srd-strong --scope global --horizon 20

# 条件前向收益统计 + 保存为 Research Asset（V8）
cargo run -p quant-cli -- research analytics --condition srd-strong --scope global --horizon 20 --save-evidence

# 季度综述：聚合 SRD / Stretch / Analytics 为 Markdown 报告
cargo run -p quant-cli -- research review --scope global --from 2026-04-01 --to 2026-07-06
```

**输出位置**：
- `research-srd` / `research-stretch` / `research analytics`：直接打印到终端
- `research analytics --save-evidence`：额外写入 `workspace/evidence/analytics/{RA-XXXXXX}.json` 并在 `workspace/registry/evidence-index.json` 登记
- `research review`：`reports/research-quarterly-{scope}-{to}.md`

**使用原则**：
- 不是买卖信号，只用于积累观察证据
- 出现 Extreme / 长期 SRD streak 时，应结合 regime + environment + rotation 一起读
- 季度末用 `research review` 汇总，作为 ADR Review 的输入
- 如果希望把单次研究产物变成可长期积累的资产，使用 `--save-evidence`，否则它只是临时终端输出

详细指标解读见 `docs/分析使用手册.md` 第 13 节。

## 12. V8 Research Asset Workspace（可选）

如果你希望把研究产物（Evidence、Snapshot）长期保存、可审计、可复现，可以使用 V8 引入的 Research Asset Workspace。它是 **V7 Research Platform 的下游产物**，不改变 V6/V7 的研究语义，只负责把研究产物以统一格式写入本地 `workspace/`。

### 12.1 目录说明

```text
workspace/
├── evidence/                    ← Evidence Asset（可复现统计证据）
│   ├── replay/                  ← Historical Replay 批量产出
│   └── analytics/               ← `research analytics --save-evidence` 产出
├── snapshots/                   ← Snapshot Asset（引用 Evidence 的计算上下文）
└── registry/
    ├── evidence-index.json      ← Evidence 索引
    └── snapshot-index.json      ← Snapshot 索引
```

- `workspace/` 默认在仓库根目录，git 忽略，不进入版本控制。
- 索引文件记录了每个 Research Asset 的 `id`（`RA-XXXXXX`）、`kind`（`Evidence` / `Snapshot`）、`version`、生命周期状态、scope、created_at、数据集 hash。
- 不要直接手动修改 `registry/*.json` 或 `evidence/` 目录下的文件；应通过 CLI 或 `app-service::workspace` API 写入。

### 12.2 日常保存 Evidence

```bash
# 保存单个条件分析为 Evidence Asset
cargo run -p quant-cli -- research analytics --condition srd-strong --scope global --horizon 20 --save-evidence
```

说明：

- 命令会先执行条件前向收益统计，与不带 `--save-evidence` 的输出一致。
- 额外把结果写入 `workspace/evidence/analytics/RA-XXXXXX.json`，并在 `workspace/registry/evidence-index.json` 中登记为 `Draft`。
- 该 Evidence 的 `dataset_hash` 和 `config_hash` 被计算并记录，用于后续复现校验。

### 12.3 批量运行 Historical Replay（推荐每日收盘后）

```bash
# 通过 PowerShell 脚本运行（已包含保存 Evidence 到 workspace）
shadow-production/historical-replay/run-historical-replay.ps1
```

说明：

- 脚本会按配置的 scope（`GLOBAL / CN / HK`）和日期窗口（默认 90 日）运行 Historical Replay。
- 每次 Replay 产生的 Evidence 自动写入 `workspace/evidence/replay/`，并登记到 `evidence-index.json`。
- 这是 V8 阶段积累资产的主要路径，建议连续运行 4 周以上。

### 12.4 查看 Research Asset 索引

当前还没有专门的 CLI 命令来列出 Research Asset，索引文件直接保存为可读 JSON：

```bash
# 查看 Evidence 索引
cat workspace/registry/evidence-index.json

# 查看 Snapshot 索引
cat workspace/registry/snapshot-index.json
```

说明：

- 索引文件只记录 metadata（id、kind、version、scope、state、hashes、refs），不重复保存完整 Evidence 内容。
- 读取索引不会访问 ClickHouse 或重新计算。
- 生命周期状态：`Draft`（刚产出）→ `Verified`（通过审计）→ `Published`（稳定引用）→ `Superseded`（被新版本替代）→ `Archived`（过期保留）。

### 12.5 使用原则与限制

- **V8 不改变 V6/V7 的研究语义**：`research analytics` 无论是否加 `--save-evidence`，计算结果完全相同；加 flag 只是额外保存一份可复现资产。
- **P3 之前不要引入 Evidence 权重**：V8 当前阶段（P0/P1/P2 完成）只负责统一格式和持久化；在 `Evidence Assets > 1000`、`Replay 稳定 > 30 天`、`Calibration 稳定 > 2 周期` 之前，不会进入 P3（Evidence Score/Weight）。
- **自行备份 workspace**：`workspace/` 是本地数据，默认不进 git，建议定期备份或上传到私有存储。
- 相关 ADR：`docs/v6/adr-079-research-snapshot.md`、`docs/v6/adr-080-research-asset-lifecycle.md`、`docs/v6/adr-081-research-asset-identity.md`。

## 13. 命令运行频率速查表（以 `scope global` 为例）

> 以下命令以 `global` scope 为主；`cn` / `hk` 是独立的分析上下文，运行方式相同，只需把 `--scope global` 替换为 `--scope cn` 或 `--scope hk`。

### 13.1 每日收盘后

| 命令 | 产出 | 作用 |
|------|------|------|
| `cargo run -p quant-cli -- sync-and-export --scope global` | `reports/daily-report-global-{date}.md` | 一键检查 gate → 刷新全链路 → 导出日报。 |
| `cargo run -p quant-cli -- research-srd --scope global` | 终端输出 | 信号与状态背离持续情况、StrongBuy 数、历史百分位。 |

| `cargo run -p quant-cli -- preclose-analysis --scope global` | 终端 + `reports/execution-samples/YYYY-MM-DD.json` | 收盘前对 signal≥Buy 的候选做 Pattern 过滤。 |
| `cargo run -p quant-cli -- data-health` | 终端 JSON + `reports/data-health-*.md` | V7 工作流：检查并导出数据健康报告（合并原 `check-data-health` + `export-data-health-report`）。 |
