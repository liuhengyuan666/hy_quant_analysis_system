# 文档状态说明

本文档用于区分当前仓库里的**实现事实**、**活跃设计**、**历史参考**与**运行产物**，避免在清理、重构和功能迭代时把不同层级的材料混为一谈。

---

## 1. 当前实现主参考（优先级最高）

这些文档描述的是当前仓库最应优先遵循的事实：

- `README.md`
- `docs/系统架构与数据流.md`
- `docs/功能模块与处理逻辑.md`
- `docs/日常操作手册.md`
- `docs/分析使用手册.md`

适用场景：

- 判断当前系统能力
- 对齐 CLI / Dashboard / report 的真实行为
- 做代码修改前确认当前实现语义

---

## 2. 活跃设计参考（仍在推进）

这些文档主要用于理解当前仍在推进的设计方向和未完成任务：

- `设计规划-v2.md`
- `docs/V2-Phase1-环境层详细技术设计.md`
- `docs/市场广度指标-MA30规划.md`
- `docs/市场广度指标-MA30-V1实施计划.md`

适用场景：

- 梳理下一阶段工作面
- 判断哪些内容是“已规划但未实现”
- 为执行模式提供设计边界

---

## 3. 历史规划 / 归档参考（不要当成当前实现契约）

这些文档保留了早期规划、阶段性评审或初版实施思路，仍有参考价值，但**不能直接当成当前实现真相源**：

- `设计规划.md`
- `实施路径-v1.md`
- `数据源方案评审.md`

适用场景：

- 回看为什么最初这样设计
- 理解某些已经收敛或已被替代的技术讨论
- 查历史背景，而不是确认当前实现细节

---

## 4. Agent / 工程元信息（不要和产品文档混用）

以下内容主要服务于 Agent 协作、工作流控制或内部计划，不属于产品功能文档：

- `TOOLS.md`
- `runtime/memory.md`
- `memory/*`
- `.sisyphus/plans/*`
- 各目录下的 `AGENTS.md`

适用场景：

- 约束 Agent 行为
- 记录当前上下文与决策
- 跟踪工作计划与代码库知识

---

## 5. 运行 / 生成产物（不是源码事实来源）

以下目录或文件主要是运行、构建或导出的结果：

- `target/`
- `apps/desktop/frontend/node_modules/`
- `apps/desktop/frontend/dist/`
- `reports/`
- `data/`
- `.idea/`

处理原则：

- 可以作为排障或回顾材料
- 不应作为代码结构或产品语义的事实来源
- 清理前要区分“可重建产物”和“用户仍可能需要保留的本地数据/报告”

---

## 6. 当前推荐读取顺序

### 代码实现前

1. `README.md`
2. `docs/系统架构与数据流.md`
3. `docs/功能模块与处理逻辑.md`
4. `设计规划-v2.md`（如涉及后续设计）
5. `memory/context.md` + `memory/decisions.md`

### 做历史判断时

1. `设计规划-v2.md`
2. `设计规划.md`
3. `实施路径-v1.md`
4. `数据源方案评审.md`

这样做的目标是：

> **先看当前真实实现，再看活跃设计，最后再看历史归档。**
