# 系统架构与数据流

本文档用于梳理当前项目的**整体架构**、**数据来源**、**数据流转路径**与**关键日期语义**。

---

## 1. 系统定位

`rust-quant-analysis-system` 是一个面向 **指数 / ETF、低频、趋势、长线** 的本地桌面量化研究系统。

当前系统目标不是做：

- 高频执行
- 自动下单
- 多用户在线服务

当前系统目标是：

- 采集日线数据
- 生成技术指标
- 结合宏观环境、轮动强弱、策略偏好生成信号
- 做基础回测
- 导出报告
- 在桌面端展示结果

---

## 2. 总体架构

```text
外部数据源
  ├─ Eastmoney（CN 指数 / ETF、HK 指数部分）
  ├─ Tencent（HK 指数与部分 fallback）
  └─ FRED（宏观因子）

        ↓

crates/data-ingestion
  ├─ universe 加载
  ├─ provider fetch
  ├─ fallback 逻辑
  └─ 日线标准化（前复权口径）

        ↓

crates/market-store
  ├─ ClickHouse 写入/读取
  └─ SQLite 本地状态

        ↓

计算引擎层（crates/*-engine）
  ├─ indicator-engine
  ├─ macro-engine
  ├─ rotation-engine
  ├─ strategy-engine
  ├─ signal-engine
  ├─ backtest-engine
  └─ report-engine

        ↓

crates/app-service
  ├─ 串联整条分析链
  ├─ 提供 CLI 能力
  ├─ 提供 Tauri 命令能力
  └─ 负责报告/健康检查/刷新编排

        ↓

应用层
  ├─ apps/cli
  └─ apps/desktop (Tauri + frontend)
```

## 3. 数据来源

### 3.1 行情数据

#### CN 指数 / ETF

- **主源**：Eastmoney
- **兜底**：Tencent

#### HK 指数

- **主源 / 组合源**：Eastmoney + Tencent

#### 当前不作为默认主源

- Yahoo Finance
- Tushare

说明：

- 当前运行环境里，Yahoo Finance 在历史接口上出现过 `403`
- Tushare 没有作为当前 V1 默认依赖

### 3.2 宏观数据

- 来源：**FRED**
- 当前使用的核心因子：
  - `VIXCLS`
  - `DGS10`
  - `DTWEXBGS`
  - `DFF`

说明：

- 当前机器上 FRED 抓取支持：
  - `reqwest` 主路径
  - Windows 下 `curl.exe` fallback

## 4. 数据口径

### 4.1 日线价格口径

当前系统统一使用：

- Eastmoney：`fqt=1`
- Tencent：`qfq`

也就是：

> **统一前复权日线口径**

### 4.2 配置元数据口径

`config/universe.json` 中：

- `symbol`：系统主标识
- `display_symbol`：展示标识
- `eastmoney_secid / tencent_symbol`：抓数标识

即：

- 展示层元数据 ≠ provider 层元数据

## 5. 核心数据流

### 5.1 行情采集与存储

入口：

- `AppContext::ingest_daily`

流程：

1. 从 `config/universe.json` 读取标的池
2. 对每个标的调用 `fetch_daily_bars`
3. `fetch_daily_bars` 内部按顺序：
   - Eastmoney
   - 失败时 Tencent fallback
4. 每根 bar 进入 `normalize_daily_bar()`
5. 持久化进入 ClickHouse `daily_bar`

输出表：

- `instrument`
- `daily_bar`

### 5.2 指标计算流

入口：

- `AppContext::compute_indicators`

输入：

- `daily_bar`

处理：

- `MA10 / 20 / 30 / 60 / 120`
- `EMA12 / EMA26`
- `MACD / signal / hist`
- `RSI14`
- `ATR14`
- `VOL_MA20 / VOL_MA60`

输出表：

- `indicator_snapshot`

### 5.3 宏观与 regime 计算流

入口：

- `AppContext::compute_macro_regime`

输入：

- FRED 因子序列
- CN anchor：`000300`
- HK anchor：`HSI`

处理分两层：

#### 第一层：`macro_snapshot`

把宏观因子转成：

- `factor_value`
- `factor_score`

#### 第二层：`market_regime`

结合：

- 宏观因子
- CN / HK anchor 趋势打分

输出：

- `trend_score`
- `liquidity_score`
- `risk_score`
- `regime_label`

### 当前 regime 特性

系统已经改成：

> **宏观因子按最近可用值向后延用（forward-fill / as-of）**

所以：

- `report_date` 可以是最新分析日
- `regime_as_of_date` 保留真实宏观参考日期
- `regime_stale_days` 显示滞后天数

输出表：

- `macro_snapshot`
- `market_regime`

### 5.4 轮动计算流

入口：

- `AppContext::compute_rotation`

输入：

- `daily_bar`

处理：

- 计算 `RS20 / RS60 / RS120`
- 合成 `momentum_score`
- 按交易日横截面排名

输出表：

- `rotation_rank`

Dashboard 展示：

- `Leaders`
- `Laggards`

### 5.5 策略偏好计算流

入口：

- `AppContext::compute_strategy_preferences`

输入：

- `daily_bar`
- `indicator_snapshot`
- `market_regime`
- `rotation_rank`

当前四类策略：

- `VALUE_LEFT`
- `TREND_PULLBACK`
- `TREND_BREAKOUT`
- `MOMENTUM_RIGHT`

输出表：

- `strategy_preference`

### 5.6 最终信号计算流

入口：

- `AppContext::compute_signals`

输入：

- `strategy_preference`
- `market_regime`
- `rotation_rank`

输出：

- `final_score`
- `signal_label`
- `explanation`

输出表：

- `signal_snapshot`

Dashboard 展示：

- `Bullish opportunities`
- `Defensive / sell watch`

### 5.7 回测流

入口：

- `AppContext::run_backtest`

输入：

- `signal_snapshot`
- `daily_bar`

处理方式：

- 多头组合
- 次日开盘成交
- 手续费 / 滑点
- 最大持仓数约束

输出表：

- `backtest_run`
- `backtest_trade`
- `backtest_equity_curve`

### 5.8 报告与 Dashboard 流

入口：

- `AppContext::dashboard_snapshot`
- `AppContext::export_report`
- `AppContext::export_data_health_report`

输入：

- `market_regime`
- `rotation_rank`
- `signal_snapshot`
- `backtest_run`
- `data_health_summary`

输出：

- `DashboardSnapshot`
- Markdown 日报
- Markdown 数据健康报告

输出表 / 文件：

- `report_snapshot`
- `reports/daily-report-*.md`
- `reports/data-health-*.md`

## 6. 桌面端刷新逻辑

当前 `Refresh data` 已改成：

> **后台异步执行 + 前端进度条 + 按钮禁用防重入**

后台步骤：

1. 计算刷新窗口
2. `ingest_daily`
3. `compute_indicators`
4. `compute_macro_regime`
5. `compute_rotation`
6. `compute_strategy_preferences`
7. `compute_signals`

前端行为：

- 显示阶段进度
- Refresh 按钮置灰
- 主 dashboard 先回填
- `Data health` 再异步补载

## 7. 关键日期语义

### `Selected analysis date`

当前正在查看的分析日期。

### `Latest available analysis`

当前系统可供选择的最新分析日期。

### `Regime as-of date`

当前 dashboard 实际采用的宏观环境日期。

### `regime_stale_days`

分析日期与宏观环境日期之间的滞后天数。

## 8. 数据健康检查流

入口：

- `AppContext::check_data_health`

当前检查项：

- 主源可达性
- fallback 可达性
- 缺口
- 异常大波动
- 缺失 turnover
- FRED 宏观源 transport（`reqwest` / `curl` / `failed`）

输出：

- `DataHealthSummary`
- Markdown 报告
- Dashboard 数据健康面板

---

## 9. 一句话概括

> **这是一个以 ClickHouse 为分析底座、以 Rust engine 为处理核心、以 Tauri 为展示容器的本地量化研究系统。**

它的核心价值是：

- 把多来源数据统一到一条分析链中
- 把原始行情加工成可解释的研究结果
- 把健康检查、信号、回测、报告、UI 放在同一个闭环中
