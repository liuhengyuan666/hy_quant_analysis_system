# 数据库架构

本文档描述系统使用的两种数据库的表结构设计：

- **SQLite**：本地轻状态存储（配置、凭据、刷新任务日志、UI 偏好）
- **ClickHouse**：分析型时序数据存储（行情、指标、宏观、信号、回测等）

---

## 1. SQLite（本地轻状态）

位置：`data/app_state.db`（相对项目根目录）

用途：存储不涉及时序分析的小型配置类数据，支持离线访问。

### 1.1 表清单

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `app_config` | 应用级配置（LLM base_url / model / timeout） | `config_key`, `config_value` |
| `job_run_log` | 后台任务执行日志 | `job_name`, `status`, `started_at`, `finished_at` |
| `ui_preferences` | 前端 UI 偏好设置 | `preference_key`, `preference_value` |
| `user_preferences` | 用户偏好（如 default_scope、last_analysis_date） | `key`, `value` |
| `credential_store` | 凭据回退存储（LLM API Key 在 keyring 不可用时） | `credential_key`, `credential_value` |
| `refresh_jobs` | 刷新任务记录（pipeline refresh 的持久化状态） | `id`, `status`, `stages_json`, `refresh_from`, `refresh_to` |

### 1.2 详细 Schema

```sql
CREATE TABLE IF NOT EXISTS app_config (
    config_key TEXT PRIMARY KEY,
    config_value TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS job_run_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    job_name TEXT NOT NULL,
    status TEXT NOT NULL,
    message TEXT,
    started_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    finished_at TEXT
);

CREATE TABLE IF NOT EXISTS ui_preferences (
    preference_key TEXT PRIMARY KEY,
    preference_value TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS user_preferences (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS credential_store (
    credential_key TEXT PRIMARY KEY,
    credential_value TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS refresh_jobs (
    id TEXT PRIMARY KEY,
    started_at TEXT NOT NULL,
    finished_at TEXT,
    status TEXT NOT NULL,
    stages_json TEXT NOT NULL,
    last_successful_stage TEXT,
    error TEXT,
    refresh_from TEXT,
    refresh_to TEXT
);
```

### 1.3 设计说明

- **所有表均无主外键关系**：SQLite 在这里作为 key-value + 日志存储使用，不需要复杂的关系约束
- **更新时间自动维护**：`updated_at` 使用 `DEFAULT CURRENT_TIMESTAMP`
- **`refresh_jobs` 的 `id` 使用 UUID 字符串**：与后端 `new_refresh_job_id()` 生成的 UUID 保持一致
- **`stages_json` 存储数组**：使用 JSON 字符串存储阶段执行结果，避免为动态阶段列表创建单独表

## 2. ClickHouse（分析型时序数据）

地址：`http://127.0.0.1:18123`

数据库：`quant`

用途：存储所有涉及时序分析的量化数据，利用 ClickHouse 的列式存储和分区能力高效处理时间范围查询。

### 2.1 表清单

| 表名 | 用途 | 分区键 | 排序键 |
|------|------|--------|--------|
| `instrument` | 标的池（指数/ETF 元数据） | 无 | `symbol` |
| `daily_bar` | 日线行情（OHLCV + turnover） | `toYYYYMM(date)` | `(symbol, date)` |
| `indicator_snapshot` | 技术指标快照 | `toYYYYMM(date)` | `(symbol, date)` |
| `macro_snapshot` | 宏观因子快照 | `toYYYYMM(date)` | `(factor_name, date)` |
| `market_regime` | 市场状态判断（趋势/流动性/风险） | `toYYYYMM(date)` | `(market, date)` |
| `environment_snapshot` | 市场环境快照（广度/压力/流动性代理） | `toYYYYMM(date)` | `(scope, date)` |
| `rotation_rank` | 轮动排名（RS + momentum） | `toYYYYMM(date)` | `(date, rank, symbol)` |
| `strategy_preference` | 策略偏好评分 | `toYYYYMM(date)` | `(symbol, date)` |
| `signal_snapshot` | 最终交易信号 | `toYYYYMM(date)` | `(symbol, date)` |
| `strategy_state` | 策略状态（全局/scope 级别） | `toYYYYMM(date)` | `(scope, date)` |
| `backtest_run` | 回测运行记录 | 无 | `(run_id, started_at)` |
| `backtest_trade` | 回测交易明细 | `toYYYYMM(trade_date)` | `(run_id, trade_date, symbol)` |
| `backtest_equity_curve` | 回测权益曲线 | `toYYYYMM(date)` | `(run_id, date)` |
| `report_snapshot` | 报告元数据注册 | `toYYYYMM(report_date)` | `(report_type, report_date)` |

### 2.2 详细 Schema

#### `instrument` — 标的池

```sql
CREATE TABLE IF NOT EXISTS quant.instrument
(
    symbol String,
    name String,
    display_symbol Nullable(String),
    instrument_type LowCardinality(String),  -- INDEX / ETF
    market LowCardinality(String),           -- CN / HK
    category LowCardinality(String),
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
ORDER BY (symbol);
```

#### `daily_bar` — 日线行情

```sql
CREATE TABLE IF NOT EXISTS quant.daily_bar
(
    date Date,
    symbol String,
    open Float64,
    high Float64,
    low Float64,
    close Float64,
    volume Float64,
    turnover Nullable(Float64),
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (symbol, date);
```

**说明**：
- `turnover` 为 `Nullable`：部分数据源（如早期 Tencent）可能不返回成交额
- 统一使用前复权数据（Eastmoney `fqt=1` / Tencent `qfq`）

#### `indicator_snapshot` — 技术指标

```sql
CREATE TABLE IF NOT EXISTS quant.indicator_snapshot
(
    date Date,
    symbol String,
    ma10 Nullable(Float64),
    ma20 Nullable(Float64),
    ma30 Nullable(Float64),
    ma60 Nullable(Float64),
    ma120 Nullable(Float64),
    ema12 Nullable(Float64),
    ema26 Nullable(Float64),
    macd Nullable(Float64),
    macd_signal Nullable(Float64),
    macd_hist Nullable(Float64),
    rsi14 Nullable(Float64),
    atr14 Nullable(Float64),
    vol_ma20 Nullable(Float64),
    vol_ma60 Nullable(Float64),
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (symbol, date);
```

**说明**：
- 所有指标字段均为 `Nullable`：边界日期（如数据起始日附近）可能无法计算完整周期指标

#### `macro_snapshot` — 宏观因子

```sql
CREATE TABLE IF NOT EXISTS quant.macro_snapshot
(
    date Date,
    factor_name LowCardinality(String),   -- vix / us10y / dollar_index / fed_funds / ...
    factor_value Float64,
    factor_score Float64,                  -- 标准化后的分数（Z-score 等）
    factor_source LowCardinality(String),  -- FRED / cached / interpolated
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (factor_name, date);
```

**说明**：
- `factor_source` 标识数据来源，支持 FRED 拉取失败时复用缓存历史
- `factor_score` 由 `macro-engine` 计算（如 252d Z-score，±3 截断）

#### `market_regime` — 市场状态

```sql
CREATE TABLE IF NOT EXISTS quant.market_regime
(
    date Date,
    macro_as_of_date Date DEFAULT date,     -- 实际宏观因子截止日（可能 forward-fill）
    market LowCardinality(String),          -- GLOBAL / CN / HK
    trend_score Float64,
    liquidity_score Float64,
    risk_score Float64,
    regime_label LowCardinality(String),    -- Favorable / Neutral / Unfavorable / RiskOn / RiskOff 等
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (market, date);
```

**说明**：
- `macro_as_of_date` 与 `date` 可能不同：宏观因子按 as-of 语义 forward-fill
- `regime_label` 当前使用 3-State Taxonomy（Favorable / Neutral / Unfavorable）

#### `environment_snapshot` — 市场环境

```sql
CREATE TABLE IF NOT EXISTS quant.environment_snapshot
(
    date Date,
    scope LowCardinality(String),           -- GLOBAL / CN / HK
    regime_as_of_date Date,
    breadth_as_of_date Date,
    stress_as_of_date Date,
    breadth_eligible_count UInt32,
    breadth_above_count UInt32,
    breadth_pct Float64,
    breadth_pct_sma5 Nullable(Float64),
    breadth_5d_delta Nullable(Float64),
    breadth_state LowCardinality(String),
    volume_expansion_pct Nullable(Float64),
    turnover_coverage_pct Nullable(Float64),
    liquidity_proxy_score Float64,
    stress_proxy_score Float64,
    environment_score Float64,
    environment_label LowCardinality(String),
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (scope, date);
```

**说明**：
- `*_as_of_date` 字段记录各维度数据实际截止日，支持跨维度时间对齐诊断
- `environment_label` 综合判断当前环境（如 Stress / Neutral / Expansion）

#### `rotation_rank` — 轮动排名

```sql
CREATE TABLE IF NOT EXISTS quant.rotation_rank
(
    date Date,
    symbol String,

    rs_60 Float64,                          -- 60 日相对强弱
    rs_120 Float64,                         -- 120 日相对强弱
    momentum_score Float64,                 -- 综合动量评分
    rank UInt32,                            -- 当日排名
    updated_at DateTime DEFAULT now()
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(date)
ORDER BY (date, rank, symbol);
```

#### `strategy_preference` — 策略偏好

```sql
CREATE TABLE IF NOT EXISTS quant.strategy_preference
(
    date Date,
    symbol String,
    analysis_scope LowCardinality(String) DEFAULT 'GLOBAL',
    regime_basis_scope LowCardinality(String) DEFAULT 'GLOBAL',
    value_left_score Float64,
    trend_pullback_score Float64,
    trend_breakout_score Float64,
    momentum_right_score Float64,

    confidence Float64,
    alignment UInt8,                        -- 信号一致性程度
    updated_at DateTime DEFAULT now()
```

**说明**：
- `analysis_scope` 和 `regime_basis_scope` 是 V2+ 引入的显式溯源字段
- `alignment` 表示四类策略评分的一致程度（高 = 分歧小，低 = 分歧大）

```sql
CREATE TABLE IF NOT EXISTS quant.report_snapshot
(
    report_date Date,
```

## 3. 设计原则

### 3.1 为什么用两种数据库

| 维度 | SQLite | ClickHouse |
|------|--------|-----------|
| 数据特性 | 小、配置类、低频更新 | 大、时序、批量写入 |
| 查询模式 | 点查（key-value） | 范围扫描（时间区间） |
| 容量预期 | < 10MB | GB 级 |
| 离线可用 | ✅ 本地文件 | ❌ 需 Docker 服务 |
| 并发写入 | 低（单用户） | 中等（后台刷新） |

### 3.2 ClickHouse 设计要点

- **所有时序表按 `toYYYYMM(date)` 分区**：支持高效按月份裁剪历史数据
- **排序键覆盖查询模式**：如 `daily_bar` 按 `(symbol, date)` 排序，支持快速单标的时序查询
- **广泛使用 `LowCardinality(String)`**：regime_label、scope、market 等枚举型字段使用该类型，压缩比高
- **`updated_at` 默认 `now()`**：便于追踪数据新鲜度，但不参与主排序
- **显式 provenance 字段**：`analysis_scope`、`regime_basis_scope`、`signal_scope` 等字段支持多 scope 并存时的溯源诊断

### 3.3 Schema 演进规则

| 操作 | 要求 |
|------|------|
| 新增列 | 使用 `Nullable(T)` 或 `DEFAULT` 值，确保旧数据兼容 |
| 修改列类型 | 需要重建表或使用 `ALTER TABLE`（ClickHouse 支持有限，通常重建） |
| 新增表 | 在 `sql/clickhouse/001_init.sql` 和 `market-store/src/lib.rs` 的 `ensure_*` 函数中同步添加 |
| 删除列 | 谨慎操作，优先标记废弃而非物理删除 |

## 4. 常用查询示例

### 4.1 查询某标的最近 30 日行情

```sql
SELECT * FROM quant.daily_bar
WHERE symbol = '000300' AND date >= today() - 30
ORDER BY date DESC;
```

### 4.2 查询某日期所有信号

```sql
SELECT * FROM quant.signal_snapshot
WHERE date = '2026-06-05' AND analysis_scope = 'GLOBAL'
ORDER BY final_score DESC;
```

### 4.3 查询最新市场环境

```sql
SELECT * FROM quant.environment_snapshot
WHERE scope = 'GLOBAL'
ORDER BY date DESC
LIMIT 1;
```

### 4.4 查询回测交易明细

```sql
SELECT * FROM quant.backtest_trade
WHERE run_id = '<uuid>'
ORDER BY trade_date;
```

### 4.5 查询报告注册表

```sql
SELECT * FROM quant.report_snapshot
WHERE report_type = 'DAILY_REPORT'
ORDER BY report_date DESC
LIMIT 10;
```
