# 功能模块与处理逻辑

本文档按模块梳理当前系统的职责边界、数据来源、输入输出与主要处理逻辑。

---

## 1. 模块分层

当前系统可分成 4 层：

1. **配置与数据源层**
2. **分析引擎层**
3. **编排与存储层**
4. **应用与展示层**

---

## 2. 配置与数据源层

## 2.1 `config/universe.json`

### 作用

定义当前分析标的池。

### 主要字段

- `symbol`
- `name`
- `display_symbol`
- `instrument_type`
- `market`
- `category`
- `eastmoney_secid`
- `tencent_symbol`
- `enabled`

### 输出给谁

- `data-ingestion`
- `app-service`

---

## 2.2 `crates/data-ingestion`

### 作用

负责所有外部数据抓取。

### 数据来源

- Eastmoney
- Tencent
- FRED

### 核心逻辑

- `load_universe()`：加载标的池
- `fetch_eastmoney_daily_bars()`：主源拉取日线
- `fetch_tencent_daily_bars()`：fallback 日线
- `fetch_daily_bars()`：统一抓数入口
- `fetch_fred_series()` / `fetch_fred_series_with_status()`：拉宏观因子
- `normalize_daily_bar()`：统一日线校验

### 输出

- `DailyBar`
- `MacroFactorSeries`

### 当前规则

 - 日线统一为前复权口径
 - provider fallback 在这里完成
 - 宏观支持 FRED API 主路径（`api.stlouisfed.org/fred`），支持配置开关（`config/fred.toml`）
 - FRED 获取可配置：启用时通过 API 获取，禁用时使用 ClickHouse 已存数据
 - FRED 限流：500ms 请求间隔，API Key 通过 `config/fred.toml` 配置（支持环境变量插值）

## 3.2 `crates/macro-engine`

### 输入

- `MacroSnapshot`
- CN anchor（日线）
- HK anchor（日线）

### 输出

- `MarketRegimeSnapshot`
- `EnvironmentSnapshot`

### 处理内容

- 因子分数
- 趋势分数
- 风险分数
- 流动性分数
- scope-aware regime（`GLOBAL / CN / HK`）
- environment layer 分解字段

- `macro_as_of_date`

- 宏观因子支持 **as-of forward-fill**
- 但保留真实 `macro_as_of_date`
- 部分 FRED 因子临时失败时，会复用已持久化 `macro_snapshot` 历史重建 regime / environment

### V3 进度输出

长耗时命令（`refresh-all`、`sync-and-export`、`compute-*`）默认向 stderr 输出进度：
```
[1/7] Starting ingest...
[2/7] Computing indicators...
...
[7/7] Running backtests...
```
使用 `--quiet` 可完全抑制进度输出，仅保留 stdout JSON。

## 9. `research-skills`（V4 新增）

### 作用

LLM 智能分析的技能框架。负责加载技能定义、管理 Agent Profile、执行技能路由、调用 LLM Provider。

### 核心结构

```
crates/research-skills/
├── skills/
│   ├── market-regime-reasoning.md   -- 市场状态推理技能
│   ├── rotation-analysis.md         -- 轮动分析技能
│   ├── signal-explanation.md        -- 信号解释技能
│   └── ...                          -- 其他技能（YAML front matter + markdown body）
├── src/
│   ├── lib.rs
│   ├── registry.rs                  -- SkillRegistry：加载/查询/管理技能
│   ├── skill.rs                     -- Skill 定义与触发条件评估
│   ├── agent.rs                     -- AgentProfile：system prompt + 参数 + 技能绑定
│   ├── provider.rs                  -- LLM Provider trait + OpenAiProvider + PlaceholderProvider
│   └── context.rs                   -- ResearchContext builder（从 DashboardSnapshot 构建）
```

### 技能文件格式（SKILL.md）

每个技能是一个 markdown 文件，包含 YAML front matter：

```yaml
---
name: market-regime-reasoning
description: 基于当前 market regime 和 environment 进行深度推理
priority: 10
triggers:
  - condition: regime_label != 'Neutral'
    weight: 1.5
  - condition: environment_score > 0.7
    weight: 1.2
---

## 分析框架

1. 当前市场状态概述
2. 关键驱动因素
3. 风险提示
4. 操作建议框架
```

### 技能路由机制

1. **加载阶段**：`SkillRegistry::new(skill_dir)` 遍历 `skills/` 目录，解析所有 SKILL.md
2. **评估阶段**：`evaluate_skill_triggers(research_context)` 针对当前 ResearchContext 评估每个技能的触发条件
3. **排序阶段**：按 `calculate_weight()` 结果排序，权重高的优先被选中
4. **执行阶段**：`analyze_with_skill(agent, skill, research_context)` 构建 prompt 并调用 LLM Provider

### 当前能力

- 从文件系统加载技能定义（YAML front matter + markdown body）
- 按条件动态评估技能触发权重
- 支持多 Agent Profile（不同 system prompt 和分析侧重）
- 支持 OpenAI-compatible API 和 PlaceholderProvider 降级
- 分析结果返回结构化 JSON（含 `analysis`、`risk_assessment`、`recommendation` 等字段）

### 当前特点

- 技能定义与代码分离：新增技能只需添加 SKILL.md 文件，无需重新编译
- Agent Profile 使用 YAML 格式，支持热加载（保存后立即生效）
- PlaceholderProvider 确保即使未配置 API Key，UI 也能展示示例分析
