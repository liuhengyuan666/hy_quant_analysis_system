# 功能模块与处理逻辑

本文档按模块梳理当前系统的职责边界、数据来源、输入输出与主要处理逻辑。

---

## 1. 模块分层

当前系统可分成 4 层：

1. **配置与数据源层**
2. **分析引擎层**
3. **编排与存储层**
4. **应用与展示层**

---

## 2. 配置与数据源层

## 2.1 `config/universe.json`

### 作用

定义当前分析标的池。

### 主要字段

- `symbol`
- `name`
- `display_symbol`
- `instrument_type`
- `market`
- `category`
- `eastmoney_secid`
- `tencent_symbol`
- `enabled`

### 输出给谁

- `data-ingestion`
- `app-service`

---

## 2.2 `crates/data-ingestion`

### 作用

负责所有外部数据抓取。

### 数据来源

- Eastmoney
- Tencent
- FRED

### 核心逻辑

- `load_universe()`：加载标的池
- `fetch_eastmoney_daily_bars()`：主源拉取日线
- `fetch_tencent_daily_bars()`：fallback 日线
- `fetch_daily_bars()`：统一抓数入口
- `fetch_fred_series()` / `fetch_fred_series_with_status()`：拉宏观因子
- `normalize_daily_bar()`：统一日线校验

### 输出

- `DailyBar`
- `MacroFactorSeries`

### 当前规则

- 日线统一为前复权口径
- provider fallback 在这里完成
- 宏观支持 `reqwest` 主路径 + `curl` fallback

## 3. 分析引擎层

## 3.1 `crates/indicator-engine`

### 输入

- `DailyBar`

### 输出

- `IndicatorSnapshot`

### 处理内容

- MA / EMA
- MACD
- RSI
- ATR
- VOL_MA

---

## 3.2 `crates/macro-engine`

### 输入

- `MacroSnapshot`
- CN anchor（日线）
- HK anchor（日线）

### 输出

- `MarketRegimeSnapshot`
- `EnvironmentSnapshot`

### 处理内容

- 因子分数
- 趋势分数
- 风险分数
- 流动性分数
- scope-aware regime（`GLOBAL / CN / HK`）
- environment layer 分解字段
- `regime_label`
- `macro_as_of_date`

### 当前关键特征

- 宏观因子支持 **as-of forward-fill**
- 但保留真实 `macro_as_of_date`
- 部分 FRED 因子临时失败时，会复用已持久化 `macro_snapshot` 历史重建 regime / environment

## 3.4 `crates/strategy-engine`

### 输入

- `DailyBar`
- `IndicatorSnapshot`
- `MarketRegimeSnapshot`
- `RotationRankSnapshot`

### 当前语义边界

- 这一层当前会构建 `GLOBAL / CN / HK` 对应的分析上下文

### 输出

- `StrategyPreferenceSnapshot`

### 当前四类策略

- `VALUE_LEFT`
- `TREND_PULLBACK`
- `TREND_BREAKOUT`
- `MOMENTUM_RIGHT`

---

## 3.5 `crates/signal-engine`

### 输入

- `StrategyPreferenceSnapshot`
- `MarketRegimeSnapshot`
- `RotationRankSnapshot`

### 当前语义边界

- 这一层当前输出的 `SignalSnapshot` 会显式携带 `analysis_scope` 与 `regime_basis_scope`
- dashboard / report / frontend 会继续把这些 provenance 展示出来，避免误把 signal 简化成“当前 scope 的唯一结论”

### 输出

- `SignalSnapshot`

### 输出含义

- `final_score`
- `signal_label`
- `explanation`

---

## 3.6 `crates/backtest-engine`

### 输入

- `SignalSnapshot`
- `DailyBar`

### 输出

- `BacktestSummary`
- `BacktestTrade`
- `BacktestEquityPoint`

### 当前处理逻辑

- 多头组合
- 次日开盘成交
- 手续费 / 滑点
- 最大持仓数控制

### 当前用户面语义

- 最新 backtest 会继续暴露 `analysis_scope` / `signal_scope` / `regime_basis_scope`
- 同时暴露它是否与当前 snapshot 匹配

## 4. 编排与存储层

## 4.1 `crates/market-store`

### 作用

系统所有数据库读写都集中在这里。

### 当前负责

- ClickHouse 初始化与读写
- SQLite 初始化与轻状态
- 各类 snapshot 存取
- backtest 结果持久化
- report 记录持久化

### 当前风险点

- 文件体积大
- 读写逻辑耦合多

---

## 4.2 `crates/app-service`

### 作用

统一编排层。

### 当前负责

- 初始化存储
- seed universe
- ingest 数据
- 运行各分析步骤
- 运行回测
- 构建 dashboard snapshot
- 导出报告
- 数据健康检查
- 后台 refresh 编排
- **V3**：sync-and-export 一键同步导出编排
- **V3**：LLM 配置管理（`set_llm_config` / `get_llm_config`）
- **V3**：LLM API Key 管理（keyring 优先，SQLite fallback）
- **V3**：LLM 报告分析（`analyze_report_with_llm`）
- **V3**：Progress callback 基础设施（CLI 进度输出支持）

### 当前关键特点

- CLI 与 Tauri 都复用这里
- 当前是业务流程大脑
- V3 LLM 方法（`set_llm_config`、`get_llm_config`、`set_llm_api_key`、`get_llm_api_key`、`analyze_report_with_llm`）直接定义在 `lib.rs` 中
- Progress callback 支持 7 阶段进度通知：ingest → indicators → macro → rotation → strategy → signals → backtests

## 5. 应用与展示层

## 5.1 `apps/cli`

### 作用

命令行入口。

### 当前常用能力

- 初始化
- 拉取数据
- 计算指标 / 宏观 / 轮动 / 策略偏好 / 信号
- 回测
- dashboard snapshot
- scope-aware dashboard/report
- report export
- 数据健康检查
- **V3**：`sync-and-export` — 一键同步导出（推荐默认路径）
- **V3**：`set-llm-config` — 配置 LLM 参数（base_url / model / timeout）
- **V3**：`set-llm-api-key` — 设置 API Key（存储在 OS keyring 或 SQLite）
- **V3**：`analyze-with-llm` — 发送报告给 LLM 分析
- **V3**：`--quiet` 全局选项 — 抑制 stderr 进度输出

### V3 进度输出

长耗时命令（`refresh-all`、`sync-and-export`、`compute-*`）默认向 stderr 输出进度：
```
[1/7] Starting ingest...
[2/7] Computing indicators...
...
[7/7] Running backtests...
```
使用 `--quiet` 可完全抑制进度输出，仅保留 stdout JSON。

## 5.3 `apps/desktop/frontend`

### 作用

桌面端展示层。

### 已实现功能

- Dashboard 总览
- Scope selector（`GLOBAL / CN / HK`）
- 历史日期选择
- Jump to latest
- Refresh stage selector（可从 `ingest / indicators / macro / rotation / strategy / signals / backtests` 开始继续跑）
- Retry failed stage
- Environment layer 面板
- Leaders / Laggards
- Bullish / Defensive signal 分组
- Recent reports（支持回跳 matching snapshot / open artifact / copy path）
- Data health
- Help / Usage 内嵌说明
- 后台刷新进度条

### 当前特点

- Vue 3 + Plain JS 混合架构，已完成 Vue 3 迁移（20+ Vue 组件）
- 国际化支持（中/英语言切换，右上角 LanguageToggle，vue-i18n@11）
- 通过 Tauri `invoke()` 拿数据
- 当前更像研究控制面板，而不是多页业务系统

## 7. 当前最重要的处理逻辑总结

### 趋势核心

- `MA20`
- `MA60`
- `MACD`

### 宏观核心

- 市场环境风向判断
- 非逐笔交易信号替代品

- 谁强
- 谁弱
- 谁在掉队

- 动能
- 宏观环境
- 轮动强弱

## 8. 一句话概括模块关系

> `data-ingestion` 提供原料，`*-engine` 负责分析，`market-store` 负责落库，`app-service` 负责编排，`apps/cli` 和 `apps/desktop` 负责给人使用。
