> **版本**: V5  
> **更新日期**: 2026-06-23  
> **适用对象**: 日常操作者、测试人员、新上手开发者

## 一、系统概述

`rust-quant-analysis-system` 是一个面向 **指数 / ETF、低频、趋势、长线** 的本地桌面量化研究系统。当前版本为 **V5**，核心架构如下：

```
数据层：Eastmoney / Tencent / FRED → ClickHouse + SQLite
计算层：指标 → 宏观 → 轮动 → 策略 → 信号 → 回测
执行层：Pattern Library（收盘前执行过滤）
研究层：5 个按钮的只读叙事分析（Market Story / Explain Decision / ...）
展示层：Tauri 桌面端（Vue 3）+ CLI
```

**V5 包含两大核心能力**：
1. **Execution Layer（Pattern Library）**：基于实时行情数据的收盘前执行过滤器，回答 "When to buy"。
2. **Research Layer（V4.5 重构）**：删除 Skill Framework，收敛为 5 个按钮 + Markdown 纯文本输出。

**关键约束**：
- Research Layer 是**只读叙事层**：只解释、质疑、提供上下文，**绝不创建信号、评分、排序或修改决策**。
- 90 天 Shadow Production 观察期：禁止新增 Pattern、前端面板、定时调度、Backtest v2、参数优化、性能声称。
- 所有 LLM 输出为 **Markdown 纯文本**，无 JSON schema、无 confidence、无 score、无 ranking。
- Execution Layer 90 天内仅作为**观测工具**，禁止声称性能优势或优化参数。

## 二、首次安装与初始化（只做一次）

### 2.1 环境要求

- **Windows**（推荐）
- **Rust toolchain**（`cargo` 可用）
- **Node.js / npm**（用于前端构建）
- **Docker Desktop**（用于 ClickHouse）

### 2.2 初始化步骤

```bash
# 1. 启动 ClickHouse
docker compose -f infra/docker/docker-compose.yml up -d

# 2. 初始化数据库结构
cargo run -p quant-cli -- init-storage

# 3. 导入标的池
cargo run -p quant-cli -- seed-universe

# 4. 构建前端
cd apps/desktop/frontend
npm install
npm run build
```

> **验证**：Docker 运行后，确认 `127.0.0.1:18123` 可访问。前端构建完成后，`apps/desktop/frontend/dist/` 目录存在。

## 三、日常使用流程（每日收盘后）

### 3.1 推荐默认路径：桌面端 `Refresh data`

1. 打开桌面端：`cargo run -p quant-desktop`
2. 点击顶部 **Refresh data** 按钮
3. 等待刷新完成（进度条显示各阶段状态）
4. 按以下顺序阅读：
   - **Trust summary** → 判断结果是否可信
   - **Pipeline freshness** → 确认数据链完整
   - **Data health** → 确认数据质量
   - **Market regime / Environment / Rotation / Signals / Backtest** → 读取分析结果

### 3.2 替代路径：CLI 一键同步导出

```bash
# 最推荐的 CLI 每日更新方式
cargo run -p quant-cli -- sync-and-export --scope global
```

- 自动检查 latest gate 状态
- 若数据落后，自动执行全链路刷新
- 刷新完成后自动导出日报
- 若 gate 未通过，会 fail-loud 并提示排查

### 3.3 分步执行（工程/排障路径）

> **以下命令必须按顺序执行，不能倒序。**

```bash
# 1. 拉取日线数据
cargo run -p quant-cli -- ingest-daily --from 2026-06-01 --to 2026-06-23

# 2. 计算技术指标
cargo run -p quant-cli -- compute-indicators

# 3. 计算宏观与市场环境（同时重建 regime / environment / strategy_state）
cargo run -p quant-cli -- compute-macro --from 2026-01-01 --to 2026-06-23

# 4. 计算轮动强弱
cargo run -p quant-cli -- compute-rotation

# 5. 计算策略偏好
cargo run -p quant-cli -- compute-strategy-preferences

# 6. 生成最终信号
cargo run -p quant-cli -- compute-signals

# 7. 检查各阶段日期
cargo run -p quant-cli -- pipeline-dates

# 8. 数据健康检查
cargo run -p quant-cli -- check-data-health

# 9. 导出日报
cargo run -p quant-cli -- export-report
```

### 3.4 快速排查工具

```bash
# 解释为什么最新日期没上去
cargo run -p quant-cli -- explain-latest-gate

# 查看数据健康状态
cargo run -p quant-cli -- check-data-health
```

## 四、Research Layer 使用指南（V4.5）

### 4.1 核心原则

Research Layer 是**冻结量化引擎之上的只读叙事层**：
- ✅ 只读：解释、质疑、提供上下文、讲述历史
- ❌ 禁止：创建信号、评分、排序、覆盖决策、参与执行
- 📝 输出：Markdown 纯文本，无 JSON schema、无 confidence、无 score、无 ranking

### 4.2 五个研究动作

| 按钮 | 中文名 | 角色 | 用途 |
|------|--------|------|------|
| **Market Story** | 市场叙事 | 资深研究员 | 今天市场发生了什么 |
| **Explain Decision** | 解释决策 | 系统分析师 | 为什么系统做出这样的决策 |
| **Preclose Review** | 收盘前复核 | 执行分析师 | 为什么 Execution 给出这样的建议 |
| **Risk View** | 风险视角 | 风控总监 | 我最担心什么 |
| **Devil's Advocate** | 唱反调 | 质疑者 | 系统可能错在哪里 |

### 4.3 使用方式

**桌面端**：
1. 点击 Dashboard 顶部 **「智能分析」** 按钮
2. 从 5 个按钮中选择研究动作
3. 等待 LLM 返回 Markdown 分析报告
4. 点击 **导出** 保存为 `reports/llm-analysis-{scope}-{date}.md`

**CLI**：
```bash
# 分析当前最新日报
cargo run -p quant-cli -- analyze-with-llm --scope global --action market_story

# 可用 action：market_story / explain_decision / preclose_review / risk_view / devils_advocate
```

### 4.4 LLM 配置（首次使用）

```bash
# 配置 LLM 参数
cargo run -p quant-cli -- set-llm-config \
  --base-url https://api.openai.com/v1 \
  --model gpt-4o \
  --timeout-secs 60

# 设置 API Key（优先 OS keyring，失败回退 SQLite）
cargo run -p quant-cli -- set-llm-api-key --key sk-xxxxxxxxxxxxxxxx
```

### 4.5 重要说明

- **V4.5 已删除**：Agent Profile、Skill Registry、技能路由、比较分析、历史记录
- 系统传给 LLM 的数据**不包含** signal score、RS score、backtest CAGR/Sharpe/MaxDD
- 只传 symbol + label + rank order，防止 LLM 成为 Meta Decision Layer

## 五、V5 Execution Layer（收盘前执行过滤）

### 5.1 用途

基于实时行情数据，回答 **"When to buy"**（什么时候买），不回答 **"What to buy"**（买什么）。

### 5.2 使用方式

```bash
# 收盘前分析（默认 global）
cargo run -p quant-cli -- preclose-analysis

# 指定 scope
cargo run -p quant-cli -- preclose-analysis --scope cn
```

### 5.3 输出示例

```text
Scope: CN
Date: 2026-06-23
Candidates: 8 (filtered: signal≥Buy ∩ state≠NO_TRADE)

Symbol       Signal       State        Reasons
------------------------------------------------------------
512480       -            BUY_NOW      StrongClose, HighVolume
510300       -            NO_CHASE     GapUpOverextended, VolumeSpike, FarFromMA5
000688       -            WAIT         (no pattern match)
```

### 5.4 约束

- 90 天内仅作为**观测工具**，禁止声称性能优势或优化参数
- 只分析 `signal ≥ Buy` 且 `state ≠ NO_TRADE` 的候选
- 实时数据来自 Tencent API，失败时全部降级为 `Skip`

## 八、常见问题排查

### 8.1 `export-report` 失败

```bash
# 先看 gate 状态
cargo run -p quant-cli -- explain-latest-gate

# 常见原因：
# 1. signal_snapshot 落后 → 单独运行 compute-signals
# 2. 某 stage is_latest=true 但 is_complete=false → 检查数据缺口
# 3. macro 数据缺失 → 检查 FRED 配置
```

### 8.2 `sync-and-export` 失败

- 查看返回的 JSON 中 `refresh_status` 和 `pipeline_diagnostics`
- 按 `explain-latest-gate` 提示修复对应 stage
- 修复后重新运行 `sync-and-export`

### 8.3 Research Layer 返回空内容

- 检查 LLM 配置：`cargo run -p quant-cli -- get-llm-status`（或通过桌面端查看）
- 检查 API Key 是否设置：`cargo run -p quant-cli -- set-llm-api-key`
- 未配置时会自动降级为 PlaceholderProvider，输出示例文本

### 8.4 桌面端白屏/空白

- 确认前端已构建：`apps/desktop/frontend/dist/` 存在
- 确认 Tauri 配置正确：`tauri.conf.json` 指向 `../frontend/dist`
- 检查浏览器控制台（Tauri DevTools）有无 JS 错误
